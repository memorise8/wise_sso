## 업무 범위

Fantra는 기존 외부 가입신청 경로를 유지한다. GitLab·업무 대시보드는 공개 가입 대상이 아니라 허가된 직원의 접근 대상으로 다룬다. wise-sso는 통합 신원·유형·상태·서비스 접근 역할을 관리하고, 서비스별 업무 데이터와 상세 권한은 각 서비스가 관리한다.

인증 관리자 화면(`/manage/dashboard`)은 프로젝트 업무·운영 대시보드(agent-hub) 본체와 다르다. 이번에 만든 고객용·직원용 더미는 인증·세션·역할 전달만 검증한다.

## 기존에 있던 기능

FastAPI 인증 서버, PostgreSQL·Redis 저장, 이메일 가입·인증, 소셜 로그인, OIDC Authorization Code/PKCE, 서비스별 역할 검사, 관리자 API·화면, 감사 로그를 재사용했다. 인계서에는 GitLab과 agent-hub의 기존 운영 OIDC 연동이 기록돼 있다. 운영 서버의 최신 상태를 재조회한 결과는 아니다.

## 검증 증거와 적용 범위

- 정책 패키지: 로컬 DB 마이그레이션 성공, policy-check PASS 3개, 서비스별 허용/거부 조합 8개, 유형 변경·필터·감사 및 본인 보호 수동 확인.
- 중앙 세션 패키지: 로컬 DB 마이그레이션 성공, sso-check PASS 6개, 직원의 재입력 없는 이동·강제 재인증·중앙 종료·고객 차단 수동 확인.
- 오늘 변경 후 단위/관리자 HTTP/OIDC dispatch 회귀 검사: 701 passed, 12 skipped, Node Express oracle 1개 제외. 더미 검사: 20 passed. Python 소스·테스트 mypy와 변경 소스 Ruff 통과. JS는 Node DOM oracle과 문법 검사로 확인했다.
- Node Express oracle은 실행 환경 IPC 제약, 성능 collector는 기존 frozen manifest/줄바꿈 문제 때문에 별도다. 전체 테스트가 무조건 모두 통과했다고 기록하지 않는다.
- 일괄 변경은 사용자 로컬 bulk-check PASS 5개와 policy-check/sso-check 회귀가 통과했다. 사용자가 일괄 변경 화면과 관리자 브라우저 로그인 동작을 확인했다. 관리자 로그인·일괄 변경의 로컬 검증은 완료 상태로 기록한다.

로컬은 4003 인증 앱, 4444 인증 HTTPS 프록시, 4445 고객 더미, 4446 직원 더미와 전용 PostgreSQL·Redis를 사용한다. 운영 서버에 이번 정책·세션 변경을 적용한 것은 아니다.

## 고객 가입 패키지 보류

`wise-sso-customer-signup.zip`은 사용자 로컬 저장소에 적용하지 않았다. 패키지에 포함된 고객 가입 진입점, Mailpit 메일함, 서비스별 역할 부여 UI 및 signup-check는 현재 작업과 이번 커밋 범위에 포함하지 않는다. 해당 패키지 전용 검사 결과도 위 검증 수치에 포함하지 않는다.

Fantra의 실제 가입 처리 코드·DB 매핑·wise-sso 호출 여부는 아직 확인하지 않았다. Fantra의 구조를 확인한 뒤 기존 가입 경로를 유지하면서 필요한 중앙 계정 생성·연결과 서비스 승인 부분을 정한다. 별도 고객 가입 화면을 구현해야 한다는 요구사항은 확정하지 않았다.

기존 wise-sso의 이메일 가입·메일 인증 기능 자체를 삭제하거나 비활성화한 것은 아니다. 신규 고객 가입부터 서비스 이용까지의 전체 검증은 아직 완료하지 않았다.

## 반드시 남겨둘 미완료 항목

1. **고객 가입 연동·전체 검증**: Fantra의 기존 가입 경로·DB·wise-sso 연결 여부를 확인한 뒤 통합 사용자 ID, 고객 유형, 이메일/소셜 신원, 서비스 이용 승인을 검증한다. 현재 더미 검증은 준비된 계정의 로그인에서 시작했다. 별도 고객 가입 검증 패키지는 미적용·보류다.
2. **직원 초대/등록의 운영 연동**: 관리자 초대·직원의 일회용 링크 수락·직접 비밀번호 설정 기능은 구현하고 로컬 검증을 완료했다. 실제 운영 메일과 실제 사내 서비스 연동은 아직이다.
3. **소셜 가입과 중앙 SSO 연결**: 기존 /auth 소셜 callback과 /oauth2 중앙 세션의 연속 흐름. 로컬 중앙 SSO의 수동 검증은 비밀번호 OIDC 경로 기준이다.
4. **실제 서비스 연동**: Fantra 가입·승인 시점, 회원 DB 매핑, callback/토큰 계약 확보. GitLab·agent-hub 현재 설정과 자체 세션·정지 처리를 확인하고 이번 변경을 테스트 환경에서 검증한다. 기획1·2는 정보 미정이다.
5. **서비스 세션 회수·통합 로그아웃**: 중앙 세션 종료만으로 이미 열린 모든 서비스 세션이 종료되지 않는다. end_session/back-channel, GitLab 사용자 block 및 PAT/SSH 처리 범위를 별도로 정한다.
6. **client 관리**: 환경변수 설정을 DB/등록·비활성화 API/관리 화면으로 이전하는 작업은 미구현이다.
7. **운영 보완**: 운영 CORS localhost 정리, 관리자 MFA·위임, 명시적 소셜 계정 연결, Fantra JWT 역할 최소화, 고객 화면 표시명/약관, 운영 Naver/Kakao 활성화, 실제 배포/복구 검증.

Fantra 관련 정보가 확보되기 전까지 기존 temis client/audience/역할 키를 임의 변경하지 않는다. GitLab의 공개 가입/자동 생성/관리자 승인 설정도 실제 구성 확인 전에는 변경 완료로 취급하지 않는다.
