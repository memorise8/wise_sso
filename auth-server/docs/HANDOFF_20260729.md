# Wise SSO Handoff - 2026-07-29

이 문서는 다음 개발 세션에서 Wise SSO/Auth Server 작업을 바로 이어가기 위한 현재 상태 요약이다. 실제 secret, access token, refresh token 원문은 문서화하지 않는다.

## 운영 구조

```text
Auth Server: https://auth.financenow.kr
Local app:   http://192.168.0.4:4000
Postgres:    docker compose service postgres
Redis:       docker compose service redis
Service:     docker compose service app
```

Cloudflare Tunnel은 다른 서버에서 관리 중이다. 공개 도메인에서 `/admin/dashboard`는 Cloudflare 정책으로 403이 발생할 수 있어, 실험용 관리자 대시보드는 아래 경로를 사용한다.

```text
https://auth.financenow.kr/manage/dashboard
```

관리 API는 기존 `/admin/*`를 유지하고, 공개 대시보드용 alias로 `/manage-api/*`도 추가했다. 둘 다 동일한 `temis:admin` DB 권한 검사를 거친다.

## 현재 구현된 주요 기능

- Google OAuth handoff
- 이메일/비밀번호 회원가입, 이메일 인증, 로그인, 비밀번호 재설정
- Handoff code exchange
- RS256 Access Token 발급 및 JWKS/OIDC discovery
- Refresh Token rotation, DB hash 저장, revoke
- 사용자 상태 `PENDING_EMAIL_VERIFICATION`, `ACTIVE`, `SUSPENDED`, `DELETED`
- `temis:user`, `temis:admin` role 관리
- 상태/역할 변경 시 refresh token 폐기
- Redis 기반 rate limit
- Resend 이메일 발송 지원
- 관리자 사용자 관리 대시보드

## TEMIS 클라이언트 계약

```text
client_id: temis
audience:  temis
issuer:    https://auth.financenow.kr
```

허용 callback:

```text
https://financenow.kr/auth/callback
https://temis.me/auth/callback
https://ti.temis.me/auth/callback
```

Hosted login/signup 진입 시 보존해야 하는 query:

```text
client_id
redirect_uri
state
code_challenge
code_challenge_method=S256
```

성공 callback에는 `code`, `state`만 포함한다. Access Token과 Refresh Token은 URL에 넣지 않는다.

## Subject 안정화 정책

JWT `sub`는 Auth Server의 `User.id`이며, TEMIS는 이 값을 `auth_user_id`로 저장한다. 그래서 한 사람의 subject는 로그인 수단이나 재가입 때문에 바뀌면 안 된다.

현재 추가된 장치:

- `SubjectReservation`
  - `email`
  - `subjectId`
  - `reason`
- 예약된 이메일이 새 OAuth 계정을 만들면 예약 `subjectId`를 `User.id`로 사용한다.
- 이메일/비밀번호 가입은 인증 완료 시점에 예약 `subjectId`로 `User.id`를 이동한다.
- verified OAuth가 같은 이메일의 미인증 pending 계정을 만나면 pending 계정을 폐기하고 canonical 계정을 생성한다.

현재 유지 중인 subject reservation:

```text
memorise8@gmail.com -> fe997392-4227-43f1-848a-e0defa68daa5
memorise8@naver.com -> f73cda83-db95-4fa4-931a-b36d4f2d2af2
```

`memorise8@gmail.com`, `memorise8@naver.com`의 실제 User/SocialAccount/PasswordCredential은 테스트를 위해 삭제했고, reservation만 남겨 둔 상태다.

## 관리자 대시보드

URL:

```text
https://auth.financenow.kr/manage/dashboard
```

기능:

- 관리자 Access Token 입력
- 사용자 목록 조회
- 이메일/상태/역할 필터
- 사용자 상태 변경
- `temis:user`, `temis:admin` 역할 부여
- 역할 제거
- refresh token 세션 폐기
- 최근 감사 로그 조회

대시보드는 Access Token을 `sessionStorage`에만 저장한다. Refresh Token은 입력받지 않는다.

관리자 Access Token은 `temis:admin` role이 있는 사용자로 발급해야 한다. 현재 확인된 관리자:

```text
ruci.sung@gmail.com
roles: temis:user, temis:admin
```

관리자 role bootstrap:

```bash
npm run ops:grant-admin -- --email ruci.sung@gmail.com
```

실험용 access token이 필요하면 서버에서 `createAccessToken`으로 짧게 발급해서 사용한다. 토큰 원문은 문서나 Git에 저장하지 않는다.

## 현재 DB에서 주의할 계정

테스트/자동화 흔적으로 보이는 pending 계정들이 있다.

```text
*@web-library.net
status: PENDING_EMAIL_VERIFICATION
user-agent: python-requests/2.34.2
```

필요하면 운영자가 삭제하거나 별도 cleanup 스크립트로 정리한다.

현재 Gmail 실제 계정으로 확인된 항목:

```text
hkyssy@gmail.com
- Google only
- status ACTIVE
- role temis:user

ruci.sung@gmail.com
- Google
- status ACTIVE
- role temis:user, temis:admin
```

## 이메일 발송

운영 기본은 Resend다.

```text
MAIL_PROVIDER=resend
MAIL_FROM=TEMIS <no-reply@temis.me>
MAIL_REPLY_TO=contact@temis.me
RESEND_API_KEY=<secret>
```

기존 환경에서 `RESEND_ADMIN_KEY`를 넣어 둔 경우 fallback으로 읽을 수 있게 처리되어 있다. 신규 환경에서는 `RESEND_API_KEY`를 권장한다.

비밀번호 최소 길이는 현재 8자다.
